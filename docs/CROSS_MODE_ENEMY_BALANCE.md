# 跨玩法敌人数值案例：赫铎为什么在搜打撤中失控

这次问题不是主线首领的某一个倍率单独写错，而是两条内容接入路径把不相同的预算混在了一起：旧环境借用了会继续扩充的深渊候选池；新环境又把旧护卫的单体攻击预算直接转换成了首领的群体输出。只检查敌人是否出现、生命和攻击总和是否接近，无法发现这两种问题。

## 旧主题为什么会抽到主线规格的赫铎

原搜打撤三个主题 `ruins`、`forest`、`sanctum` 的首领候选取自 `catalog.AbyssData.pools.boss`。新增赫铎进入深渊候选后，这三个旧主题也随之可能抽到他。但“来自深渊候选池”并不意味着战斗会使用深渊数值：搜打撤配置标记为 `isExtraction`，敌人创建时仍读取 `baseStats`，而非 `abyssBaseStats`。同时，赫铎的搜打撤归一只配置在 `lantern` 主题，旧主题没有这层转换。

| 实际入口 | 赫铎使用的基础或预算 | 本次处理 |
| --- | --- | --- |
| 主线第三章 | `baseStats`：生命 16,000、攻击 235 | 保留章节自身成长与挑战，不为修复搜打撤统一削弱 |
| 深渊 | `abyssBaseStats`：生命 4,500、攻击 125；按深渊曲线成长 | 保留独立预算与候选 |
| 搜打撤 `lantern` | 赫铎与双灯先按同幕旧首领预算归一，再乘搜打撤成长 | 保留主题遭遇，修正高阶护卫攻击折算 |
| 搜打撤三个旧主题 | 修复前可能直接拿到生命 16,000、攻击 235，再乘搜打撤成长 | 首领候选明确固定为 `boss_flame_lord`、`boss_storm_witch` |

修复没有从深渊删除赫铎，也没有更改主线基础属性。它切断的是旧主题对深渊动态候选池的隐式依赖。定向检查特意把深渊首领池临时设成只有赫铎，确认三个旧主题仍只生成原两名首领、保留原护卫，并且不改写深渊候选池。这样的检查才能证明边界确实存在，而不是恰好一次没有抽到新怪。

## 新主题为什么在高阶仍然过强

`lantern` 的首领编队是赫铎加两盏侧炉灯。归一前总生命为 `16000 + 2800 × 2 = 21600`，总攻击为 `235 + 30 × 2 = 295`。参考的两名旧首领平均生命为 4,750、平均攻击为 130；新主题仍使用生命比 1.08、攻击比 1.05。

旧搜打撤在难度 4 增加一名黑暗骑士，生命 1,200、攻击 90；难度 5 再增加雷鹰，生命 420、攻击 80。原归一把这些护卫的生命、攻击全额加进 `expected`，再按新编队的基础属性比例分配。结果，原本由护卫承担的单体攻击，大部分按 `235/295` 的比例转给了会群攻的赫铎。它不是同一份攻击换了一个外观，而是改变了命中人数、技能倍率和持续伤害的载体。同一套三回合算式在零防御下显示，原高阶归一使难度 4/5 的群体总伤害约为旧首领连同护卫平均值的 1.4–1.7 倍；这是下文限定条件下的算式结果，不是实战通关统计。

本次调整只改变高阶首领的攻击换算：护卫生命完整保留，护卫攻击按 25% 计入；难度 0–3 没有护卫预算，因此保持不变。

```text
参考生命 = 4750 + 护卫生命总和
参考攻击 = 130 + 护卫攻击总和 × 0.25
主题 hpMod = 参考生命 × 1.08 / 21600
主题 atkMod = 参考攻击 × 1.05 / 295
```

末幕首领节点的实际攻击还要经过原有幕数、难度和首领修正。以本次断言使用的第三幕、第 4 节点为例：

```text
C = (0.65 + 0.03 × 14) × rankAtk × 1.65 × 0.85
赫铎攻击 = int(235 × 主题 atkMod × C × 1.15)
难度 4：护卫攻击 90，rankAtk 50，赫铎攻击 11006
难度 5：护卫攻击 170，rankAtk 90，赫铎攻击 22410
```

这里的末幕 1.15 只对真正首领应用一次，不给旧编队护卫重复加成。25% 是这次结合具体技能输出选定的转换比例，不是未来所有怪物都能套用的常数。

## 要比较的是造成伤害的过程，不只是攻击栏

赫铎一阶段有 1.7 倍单体重锤、0.9 倍全体伤害并施加燃烧；二阶段有 1.6 倍全体伤害和 2.1 倍单体伤害，这四个技能的冷却均为 0。侧炉灯每次行动提供持续一回合的 15% 攻击增益；两灯通过持续时间维持覆盖，不应当作两个独立 15% 乘区。燃烧按施加者攻击记录计算，每次结算为 18%，不走直接伤害的防御和护盾吸收路径。

因此，同样增加 90 点攻击，放到黑暗骑士的单体技能和放到赫铎的全体技能上，不会产生相同威胁。只用零防御目标比较也不够：防御 500 会把普通直接伤害的防御系数降到 `100 / (100 + 500)`，燃烧却不会一起变成六分之一。

### 三回合算式的范围

本次参照是中性属性三人队、固定三个回合的有限技能分支计算，分别固定在一阶段或二阶段，并分别采用防御 0 与 500。直接伤害计入敌人的 10% 暴击率、1.5 倍暴伤及整数取整；旧首领自身增益、护卫行动与相关冷却、新首领双灯增益和燃烧按各自分支计入。两灯与三名目标假定一直存活，双灯从第二回合起维持 15% 攻击增益；黑暗骑士按高于半血的动作选择计入冷却 2 的护盾，雷鹰按 1.2 倍单体行动计入。每个阶段都从空状态单独起算，不模拟玩家输出、击杀灯、治疗、控制、减伤或护盾。实际进入二阶段会继承已施加的燃烧和旧首领自身增攻，本表刻意隔离阶段，不能直接当作跨阶段战斗轨迹。

对照分母是“炎王连同该阶护卫”和“女巫连同该阶护卫”的三回合全队总伤害平均值，不是只拿旧首领本体比较。它用于识别预算转换的问题，是设计参照，不是玩家通关率、实战录像或完整难度等价证明。

高防御下一阶段仍有差距，说明绕过防御的燃烧不能被面板攻击的校准自动抵消。保留这个结果比把修复描述成“全部玩法已经一样强”更有用。未来若继续调整，应明确是在处理持续伤害、灯的覆盖或技能节奏，不能为了压平一张表顺手削弱主线、深渊和所有低阶遭遇。

## 已经生成的战斗和场景也要有明确边界

新预算与候选规则作用于新生成的遭遇。已签发的 `activeEncounter` 保留敌人、倍率、种子和配置；`prepare_battle()` 只返回既有配置副本，不重新抽敌、不重算攻击、不消耗新的随机数。不能借修复之名暗中改写玩家正在进行的战斗或存档。

本次场景修复沿用同一原则：地图节点生成时已经确定 `node.background`，新战斗将当前房间的背景冻结进 `config.background`，而不是进入战斗后重新抽图。旧战斗缺少此字段时，仅在显示层只读回退到已存房间、节点、区块或主题背景；既不写回已签发配置，也不改变 RNG 和原有地图音乐。

新内容还会改变界面高度。本批试用完成后的抽卡页曾需要关注底部单抽、十连和试用入口，放弃搜打撤的说明与取消、确认按钮也必须同时可见。后续新增信息应放进固定页的可用区域，必要时让内容区域滚动，不能让整页继续增高把操作按钮挤出屏幕。背景一致、文本可读和按钮可达应在同一次真实界面检查中确认。

## 下次新增怪物时，先把这些具体关系写出来

为每个新敌人列出主线、深渊、搜打撤分别使用的候选池、基础属性入口、成长曲线、编队和技能差异；新增内容接入三种模式，不等于三个模式共用一个会自动扩充的候选池。需要共享标识时仍要显式声明每个模式的预算与准入规则，并检查没有新增内容的旧主题是否意外变化。

比较同层同类遭遇时，既记录生命、攻击、防御、速度，也记录群攻命中人数、倍率、冷却、行动顺序、阶段转换、附属单位的增益覆盖、持续伤害是否绕过防御或护盾，以及旧敌队实际携带的护卫。至少把低防御与有代表性的高防御条件分开看。若把一个单位的预算转给另一个单位，先问输出方式是否改变，再决定转换系数。

最后把新生成遭遇、已签发遭遇和旧存档分开验收：前者验证新候选与新预算，后两者验证配置与随机状态保持。真实界面再确认本节点背景和关键按钮，而不是只证明资源文件存在。范围按该次实际变更选择，沿用必要受影响检查的时间预算，不因此扩成全量长测。
