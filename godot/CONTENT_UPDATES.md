# GitHub 内容更新

本版加入独立启动场景。已经安装的 2.9.2 先通过原有 GitHub 更新入口安装一次同包名、同签名的完整迁移 APK，存档保留。此后，相同平台的更新下载完整游戏逻辑包及本机缺少的素材包，完全关闭游戏再打开后应用。

游戏逻辑包含实际 Android 导出后的脚本、场景、数据和导入映射。素材以实际导出的纹理、音频、字体字节为单位分别打包，用 SHA256 标识。客户端检查 APK 自带资源和持久缓存，只下载目标版本缺少的对象；完整目标清单支持跨多个版本直接升级。初次安装和原生平台变化继续使用完整 APK。

每份内容清单由长期 Android 发布私钥使用 RSA SHA256 签名。启动器内固定对应公钥，先验签并检查来源、版本、平台标识、长度和哈希，随后挂载素材与逻辑，最后加载真正的游戏场景。平台标识覆盖启动器、引擎安装配置、Android 构建配置和原生文件；这些内容变化时使用 APK 更新。发布端同时保留完整 APK，兼容旧更新器。

素材对象发布在同仓库独立的 `android-v版本-assets` 预发布记录中；正式记录仅包含 APK、校验文件、清单和签名。这样旧客户端读取正式版本信息时保持较小响应。历史清单引用的素材发布记录应永久保留；发布过程复用经签名验证的已有对象地址。

下载使用临时文件，完整校验后移入持久缓存。已经下载完成的对象在取消、断网或进程退出后保留，重试只补缺少的对象。全部资源就绪后原子保存待激活记录。新版本首次启动前快照备份存档，游戏初始化成功后确认版本；首次初始化中断时，下次启动恢复上一版本及对应存档快照。损坏的恢复记录或备份保持原文件并停止启动，避免覆盖存档。

APK 自带的基础资源继续随完整平台包分发。成功启动后按完整签名清单回收失去引用的素材缓存，保留当前版本、上一可回退版本、待激活版本及中断下载所需对象；记录异常时保留文件。存档快照继续保留，便于人工恢复。内容下载在游戏运行期间进行；后台进程被系统终止后，在下一次检查时利用已经完成的对象继续。单个未完成对象重新下载。

## 验证入口

`python3 godot/tests/test_content_transfer.py` 检查真实 HTTP 传输、签名验证、失败重试与差量对象选择。

`python3 godot/tests/test_content_bootstrap.py` 检查激活、启动失败恢复和存档回退。

`godot --headless --path godot --script res://tests/test_content_save_guard.gd` 检查存档快照和幂等恢复。

`python3 godot/tests/test_content_release.py` 检查确定性构建与真实导出资源复用。

实际 Android 覆盖安装、完整签名 APK 构建和公开 GitHub 下载仍以对应发布验收记录为准。
