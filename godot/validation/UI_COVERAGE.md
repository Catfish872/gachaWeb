# 虚空裂变：原生界面与视觉验证

本项目使用 Godot 4.6.3 的 Control、Container、Canvas 绘制与 Tween 动画实现完整界面。入口为 `main.tscn`，界面控制器为 `scripts/main.gd`，背景与战斗特效位于 `scripts/ui/`。角色成长、抽取、装备、商店、关卡、深渊与存档操作调用 GameModel；战斗技能、目标合法性、敌方行动与结果调用 BattleModel。界面根据引擎事件播放视觉反馈。

## 界面与内容覆盖

营地采用原始荒原背景、章节入口、活动祈愿、深渊入口、出战角色与旅程统计。世界探索显示两个章节、十个关卡、解锁条件、敌人、波次、体力与首通奖励，并连接全部二十段战前／战后剧情，共一百三十三行对白。对白支持逐字显示、首次点击补全文本、继续、跳过与通关后的剧情回顾，立绘遵循原始 portrait 字段。

祈愿覆盖常驻与限定池、单抽、十连、逐张翻面、全部揭示、结果网格、重复抽取、角色碎片、当前五星概率与保底状态，余额不足时抽取按钮禁用。抽取按钮位于画面上方，限定池说明展示原版实际生效的非大保底五星限定概率 75%，以及大保底 100%；软保底首次提升对应第 74 抽。所有概率与抽取结果由模型计算。

编队与角色图鉴覆盖全部十位已拥有／待获得角色、元素筛选、三个出战席位、角色称号、职业、背景、风味文字、六项属性、被动与三十个角色技能。养成提供等级／经验、金币训练、六层命座、碎片消耗、五个遗物装备位与卸下操作。金币训练为此次迁移新增的原生养成入口，费用与经验由模型统一定义。

遗物工坊提供背包／已装备／星级／部位筛选、主副属性、装备选择、卸下、逐级强化、一次强化至 +25、出售，以及三星／四星／未强化条件的批量出售。批量条件采用并集，已装备遗物受到保护。筛选、选中项与批量选项保存在本地界面设置中。

深渊提供层数、最高纪录、连续自动挑战、回响路径、角色回响偏向、三选一奖励、当前构筑、战斗内回响查看与免费／星尘晶重置。连续挑战在普通层结算后进入下一层，在回响选择处暂停；选择后可继续。关闭战斗自动模式会同时停止连续推进。原始数据中的事件／商店字段属于预留结构，本项目覆盖原版已经实现的战斗与回响循环。

商店提供金币兑换与原版全部模拟礼包；页面明确标注离线模拟、即时发放与展示价格。档案页面提供三个独立槽位、真实摘要、最后保存时间、切换、重置、即时保存，以及各槽位的导出／导入。导入与重置均有明确目标的确认界面。

## 战斗与视觉表现

战斗界面显示双方队伍、行动顺序、当前角色、回合与波次、生命、护盾、能量、冷却和状态持续时间，提供技能说明、合法目标选择、手动施放、自动行动、1／2／4 倍速、撤退确认和胜败结算。伤害、治疗、暴击与状态事件具有浮动文字；攻击具有轨迹、粒子、受击摇动与颜色闪烁，终结技具有屏幕闪光。战斗结果保存失败时保留重试入口，旧战斗的延迟结果会校验场次，避免覆盖新页面。

美术资源包含两张原始角色图、一张原始荒原图，以及十七张新绘制的 SVG 角色／敌人插画。八位缺失原画角色与九种敌人分别具有独立轮廓、武器与元素配色。SVG 已通过 XML 检查和 Godot 实际栅格化检查；`assets/portraits/contact_sheet.png` 汇总全部新增插画，`tools/create_portraits.py` 保留可复现绘制源码。覆盖现有文本和 GB2312 常用字的简体中文字体子集与符号后备字体随项目附带，授权文件位于字体目录。全部对白、角色文案、技能与回响文本的字体覆盖检查为零缺字。

## 自动化验证

`tests/test_ui.gd` 共通过 128 项界面控制器检查。检查通过真实 Button／CheckBox 信号、FileDialog 结果信号以及实际模型和战斗引擎运行，覆盖初始存档与完整角色集合、九个页面、图鉴与元素筛选、编队空位和保存、抽取与翻面／跳过、训练与命座、装备／卸下／强化至满级、槽位切换、文件导入导出、手动攻击、撤退取消与确认、完整胜利结算及战后对白。

深入检查完成前三层自动深渊战斗，验证第三层三选一暂停、选择后进入第四层、关闭自动后的停止行为；同时验证结算保存失败后的恢复重试、页面切换后的延迟结算保护、二十段对白入口，以及逐字显示的两次点击语义。最终运行日志包含 `PASS UI: 128 checks`，脚本错误数为零。项目统一验证入口为 `tools/test_all.sh`。主场景支持 `--test-session`，用于在内存存档中执行独立场景测试。

## 桌面观察与竖屏范围

桌面 Godot 实际窗口已观察营地、章节、战前对白、手动攻击、自动战斗、胜利奖励、祈愿翻面与结果布局；本目录保存营地、战斗及祈愿截图。实际观察后已调整祈愿操作位置、结果卡片均匀铺满、角色完整展示与胜利弹窗高度。

竖屏验证采用 Godot Window 实际尺寸设为 480 × 800 的自动化运行，界面根据窗口比例切换为 540 宽逻辑画布，九个页面均通过横向最小宽度边界检查。该证据属于引擎中的布局与控制器验证；设备视觉观察范围为桌面窗口，移动设备触控、Android／iOS 导出安装、真实手机画面与平台文件选择器兼容性留待对应平台验收。
