# 搜打撤节点完成自动回图

本次实现位于 NEXT。`extraction_model.gd` 新增纯查询 `room_interaction_status()` 与 `has_remaining_interaction()`，返回当前运行、房间、剩余交互原因及自动回图许可。查询使用实际可执行的房间选项、搜索物品、直接使用与装备、手动交换空间、钥匙串容量、寄送费用和接收空间，并保留战斗、守卫、成长选择及首领出口。空容器可以完成节点；超出空背包尺寸且没有直接使用或装备途径的物品继续保留在世界中。查询同时校验必要的房间与库存结构，维持物品、资源、随机状态和错误信息原样。

`extraction_view.gd` 在关闭当前容器、成功选择房间选项、完成成长选择后调用现有 `advance_room()`。寄送成功先展示反馈，反馈退出后再检查房间。关闭容器先使搜索代号和延迟自动收取失效；存档失败保留房间及原容器弹窗以便重试。完成检查采用运行编号、房间编号、搜索代号和当前模态实例校验，重复与过期回调保持幂等。`main.gd` 仅为 Android 返回键加入当前容器的专用分发；交换、摆放、寄送预览、帮助及放弃确认的取消维持原交互层，全局清理弹窗逻辑保持原样。

最终专用无界面测试 `tests/test_room_return_v250.gd` 通过 485 项检查。覆盖最后物品取空后关闭、其他未搜容器、满包交换与补给、超大物品保留、钥匙及容量边界、待战斗与成长、休整和事件、首领出口、成功与取消寄送、搜索及收取中关闭、后台恢复、快速触摸加模拟鼠标、重复关闭、过期房间与运行回调、存档失败重试，以及四种窗口尺寸下稳定地图与固定操作区。

原生鼠标坐标点击容器右上角关闭按钮，验证实际界面进入地图并保持当前节点、物品、随机状态和金币，5 项检查通过。`native-before-close.png` 与 `native-after-close.png` 为对应截图；`last-item-before-close.png` 与 `returned-map.png` 为自动交互实渲截图。最终真实 OpenGL 回归同样通过 485 项检查，结果记录于 `real-gl.log`；原生坐标回归结果记录于 `native-gl.log`。测试使用独立内存存档和隔离偏好目录。

关联回归通过：`extraction_v6` 36821 项，`extraction_ui` 1036 项，`guard_services_v241` 179 项，`service_layout_v241` 1420 项，`redesign_deposit` 367 项，`boss_parcels_v241` 2460 项，`loot_v24_interactions` 287 项，`redesign_loot_interactions` 151 项，`autoexchange_lock_v241` 191 项。旧测试复用已完成节点时，采用点击地图当前节点的真实重访步骤；守卫后的空寄存站测试先验证自动回图，再重访检查原有服务。原有物品唯一性、费用、守卫、经验与重访保持断言继续执行。

进一步回归通过：`extraction_v7` 359 项，`extraction_v8` 687 项，`extraction_map` 163262 项，`expedition_rules_v241` 449 项，`parcel_packing_v241` 102578 项。最终日志扫描清洁，真实 OpenGL 驱动仅保留平台已有的垂直同步提示。
