# 2.5.0 遗物整套装配：计算契约与验证

本实现位于 `gacha-android-next/godot/scripts/relic_optimizer.gd`，五个部位联合求解。计算只读取角色和库存，保持原等级、强化、金币、保存状态及实际战斗随机数序列。默认候选为未装备遗物和当前角色遗物；其他角色装备由原子应用层继续保护。当前版本沿用原始成长次序，包括等级暴伤 `base × 1.1^(level−1) + flat`，速度参与行动顺序和条件判定。

## 培养目标与参考条件

卡尔迪、格斯、冈、泽菲、博、辛德采用六次自身行动的期望直接伤害。技能选择与实际自动战斗一致：可用终结技立即释放，其次战技，随后普攻。初始能量为零，三个持续存活的中性目标防御为 100，其他单位速度为 100。目标状态采用角色自己能够施加的条件：火系三人的燃烧、博的感电，其余角色为空。显示文案明确说明条件状态按全程覆盖评价；这衡量该参考场景的条件潜能，队伍控制、队友增益和实际战斗持续伤害另行发挥作用。显式 `context` 可以更改参考参数。手动最优策略只有显式 `policy: optimal` 才作为主目标。

艾拉、夏娜采用六次自动行动的潜在治疗，假设三名友方持续具备足够缺失生命。主动技能治疗及角色直接治疗被动采用共享战斗公式，治疗暴击与主动治疗套装适用范围保持实战定义。满血实际恢复为零，预览仍展示声明条件下的潜在治疗；再生和护盾另行生效。

洛恩、塔德采用“施放自身护盾后的有效承伤”：`(最大生命 + 一次自身战技护盾) × 1000 / 满血时承受中性基础伤害1000的期望直接伤害`。防御、格挡、直接减伤与护盾倍率均由战斗模型计算。它明确以护盾已施放为条件；一次性无敌、持续回复和队友护盾各自保留实战作用。

`CharacterData.relicObjective` 指定主目标。技能声明的 `scalingStat` 由实际战斗和装配评价共同消费，支持攻击、最大生命、防御；自身战技护盾也按声明推导相关属性和缓存键。验证中的虚拟角色仅存在于测试内存。当前技能循环状态包含每位现有角色的一项战技冷却，新增多个独立战技时应同步扩展循环状态。

## 精确性与证明界限

候选按相同部位、相同套装与相同自动能量日程进行支配剔除。自动策略在能量断点处可能改变技能时机，因此不同能量恢复或不同有效暴击概率的物品保留各自分支；双双达到暴击上限时可以合并该维度。其余相关属性在已验证数值域内单调。剔除同时保留平分优先级：先免费补齐具备非负有效属性的原空槽，再保留原有非空装备，最后按稳定唯一标识选择。主目标始终先比较，填空槽与保留装备采用字典序规则。

每槽完整候选构成二叉树。搜索节点是五个候选区间的组合，记录逐属性上界与仍可成立的套装阈值。优先队列展开全局上界最高的节点；强分支选择使剩余最大上界更紧的分割。扫描、支配比较、建树、种子构造、强分支的各个子界均能跨帧推进。所有合法未被证明支配的候选始终保留。

完整方案采用共享战斗整数公式与自动策略的精确期望。暴击次数分布、格斯逐次暴击回能、雷套每行动一次回能、夏娜/艾拉主动治疗回能及冈六命概率回能进入能量状态转移。部分节点允许最优合法技能策略作为保守上界，因为它可以选择任何自动策略能够选择的动作。更高的可用资源与效果在这个放宽问题中保持可行策略集合扩张。

同一缩放源的快速上界把共享公式归一化为单位源值，缓存能量与暴击状态转移系数，并补充源值、伤害、主动治疗及夏娜自疗的取整误差。启用前以无遗物的最低源值逐个技能、链式命中验证原始伤害或治疗均达到最低 1 点阈值；任何无法通过的场景都回到完整共享公式上界。归一化人工源值也单独通过整数转换检查；人工源值超域而真实源值安全时，使用完整上界。混合缩放源、格斯和卡尔迪六命的额外来源也沿用完整上界。

相关属性使用加权算术—几何平均不等式进一步收紧。令源属性的平直部分为 X、百分比因子为 Y、原始暴击概率为 C、额外暴伤为 D，则连续期望源值上界为 `XY + XYCD`，同时可以利用 `min(1,C) ≤ 1` 给出 `XY + XYD`。对每个乘积，任意正权重给出合法的加权和幂次上界；每槽二叉树保存相同权重下的最大线性支持值。不同权重的上界取最小值保持有效。完整叶仍使用实际逐次整数结果。

最优性证书为 `L ≤ OPT ≤ U`，高级详情展示 `(U−L)/max(abs(L), ε)`。只有完成稳定平分选择且 `U ≤ L` 才返回 `provenOptimal=true`。中途的“当前推荐”保持真实自动战斗目标，玩家明确确认后可调用模型的 `apply_relic_loadout(plan, true)`；确认过程保留原指纹和证明字段。

旧存档允许极大的有限数值。现有整数转换在溢出后可能破坏单调性，因此预览在剪枝前检查全部已见候选的属性包络、套装、技能、能量恢复及战斗倍率。可能跨越有符号整数转换安全范围时返回清楚的计算错误，`provenOptimal=false`、`canApply=false`，存档与原成长公式保持原样。

## 应用与取消

`begin_best_relic_loadout(char_id, context)` 返回合作式搜索对象；`advance(4000)` 处理一个短时间片，`preview()` 返回当前展示方案，`cancel()` 保留游戏原状态。`preview_best_relic_loadout` 是用于测试的同步完成接口。计划指纹涵盖选中存档槽、角色成长、所有库存物品的唯一标识、等级、属性、套装、所有权、角色/技能/套装定义和参考条件。库存扫描按顺序以无损 Variant 二进制编码增量生成同一 SHA-256 摘要；缓存同样保留完整浮点位与原始速度，状态修正和全场平均值继续由共享战斗公式判定。

模型应用前重算指纹、核对当前与目标装备映射、验证唯一部位/唯一物品及所有权，并重算实际属性后一次提交。保存失败回滚整个所有权和资源状态。预览界面冻结用户最后看到的方案，再取消后台搜索并应用该副本。

## 验证与性能证据

`tests/test_relic_optimizer_v250.gd` 覆盖五槽穷举、每个中间前缀上界、六套两件/四件阈值、暴击溢出、自动能量断点、六命、未来生命/防御伤害缩放、未来攻击护盾、空槽平分、其他角色保护、取消、指纹与整数溢出域。`tests/test_relic_optimizer_battle_v250.gd` 对六名输出角色、暴击 0/100%、三个能量恢复档的六次真实自动技能执行逐一对照，并区分满血实际恢复与潜在治疗。

复核反例分别为最低 1 点伤害地板、高防御目标、继承格斯被动的新标识角色、重排技能数组、攻击缩放自身护盾，以及合法遗物极值引起的整数溢出。相应用例已进入回归测试。独立复核脚本和日志位于相邻的 `relic-optimizer-review-v250` 目录。

`profile.json` 和 `profile.log` 是当前性能数据源。100/500 件库存运行至完整证书；2000 件记录一分钟交互窗口及真实剩余界限；十万件合法库存完成全部扫描和建树，记录第一个可应用推荐后取消。它们是 Linux 无界面执行环境的实测，Android 设备耗时和峰值仍应单独验证。500 件的大库证明具有可见等待时间，明确采用当前推荐的入口保留操作连续性；候选完整性和证明门槛贯穿整个等待过程。
